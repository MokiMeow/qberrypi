# Front panel OS (round 8, home "Wall"): Implementation Plan

> **For agentic workers:** lean subagent-driven development: one fresh implementer per task, no
> per-task review, one whole-branch review at the end. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Build `docs/superpowers/specs/2026-11-12-qberrypi-panel-os-design.md` (read it first, all
of it): the lane, HOME, LIVE, DEVICES, GATE, ALERTS, NAMES, SYSTEM, the whole-system states and the
lock, and the Pi-side parts they need, in three milestones that each ship on their own with
`cargo xtask update`.

**Source of truth for the look:** the round 8 mockup folder, given to implementers as
`QBP_MOCKUP_DIR` (`README.md`, `src/screens.js`, `src/homes.js` wall only, `src/parts.js`,
`src/stage.js`, `src/common.js`, `src/d6.js`; stills `r8-wall-*@2x.png`, pixel (x, y) of the panel
is (2x, 2y) of a still). Where the JS and the spec disagree, the JS wins unless the spec's §11
lists a deviation; report any disagreement in the commit message.

**What exists:** `crates/qb-panel` (the Drain: `drain/{mod,look,paint,fixture,stamps}.rs`,
`text.rs`, `touch.rs`, `rows.rs`, `format.rs`, `state.rs`; tests `drain_golden.rs`,

`qb-dns/src/{decide,stats}.rs`. The round 6 plan `2026-11-11-panel-drain-r6.md` holds the panel's
conventions; they all still hold.

## Global constraints

- **Workspace:** the worktree `~/Work/qberrypi-panel8` (branch `panel-os`). `export
  TMPDIR=~/Work/qberrypi-panel8/target/tmp`. Use the worktree's own target folder (never a
  `CARGO_TARGET_DIR` shared with another worktree). Never read anything under
  `~/Work/qberrypi/`; never read or change a real `qberrypi.toml` (the worktree's is a
  dummy); never contact the Pi; no `git reset --hard`, no `git clean`, no push.
- **Rust only.** No new language anywhere (the mockup's JS is a reference, not a source).
- **Gates before every commit:** `cargo test --workspace`; `cargo clippy --workspace --all-targets`
  with 0 warnings; `cargo fmt --all --check`; `cargo build -p qberrypi --release --target
  aarch64-unknown-linux-musl`; `grep -rln unsafe crates/qberrypi/src crates/qberrypi/tests` prints
  only `crates/qberrypi/src/sys.rs`. A task that touches `init.rs`, `selftest.rs`, `wifi/`,
  `update/` or `xtask` also runs `cargo xtask build && cargo xtask qemu-test`.
- **Hot path (spec §6):** a task that touches `qb-dns/src/{decide,stats}.rs`, `dns/` or `lane.rs`
  runs the ignored benches before and after (`cargo test -p qb-dns --release -- --ignored
  --nocapture` and `cargo test -p qberrypi --release -- --ignored --nocapture decide_cost
  observe_costs`) and puts both sets of numbers in its commit message. A change beyond the runs'
  own spread is a failure of the task, not a note.
- **Budget:** every write within a screen ≤ 80 rows (`changed_rows`); one-off full writes only on a
  screen change, a whole-system state change, a pause toggle and Wi-Fi joining.
- **Privacy:** no name, label, MAC, address or PIN digit in a log line; no `Debug` that prints
  one (redacting `Debug` or none); tests use `example.org`/`example.com`/`.invalid` names,
  `192.0.2.x`, `02:00:00:00:00:xx`, and the mockup's invented house and public ad names.
- **Panel thread:** all rendering and `/proc` reads on the panel's pool thread; nothing on the
  runtime thread; the resolver lock is taken by the panel for copies only (spec §5.2).
- **Commits:** stage files by name; message ends with `Co-Authored-By: <implementer's model>
  <noreply@anthropic.com>`; never push.
- **Goldens:** written with `QBP_BLESS=1`, looked at beside the mockup still before committing,
  compared with `QBP_MOCKUP_DIR` set; a region the spec's §11 changes is listed as excluded.

## Review focus (the final review)

1. The answer path: the bench numbers in the commits of Tasks 5 and 8; the empty owner list
   costs two `is_empty` checks; `watched == 0` costs one relaxed load; no new lock on the path.
2. Tap routing against the README's map: every door, the three fixed places, idle home, the alert
   arrival rule, strong intents and the PIN, screens that pop when their thing goes.
3. Writes ≤ 80 rows inside a screen; the Drain's budget unchanged.
4. The lock: digits zeroized, constant-time verify, backoff, no digit or hash in a log or an
   answer; strong set exactly spec §7.1.
5. Sync with qnet: `rev` moves on every edit by anyone; `if_rev` 409s; panel edits land in the
   pushed lists of the mode in force; config-fixed devices are inert.
6. Memory: VmRSS growth ≤ 5 MB (spec §6.7) by the painters' and caches' sizes.

## Pi checks (the owner, after each `cargo xtask update`)

Each milestone appends its list here as unchecked boxes. Always: `cargo xtask latency` before the
update and after (cached, blocked, forwarded p50/p99 within the spread); the resident memory
before and after (≤ 5 MB growth over all three milestones): the Pi has no shell, so it is read from
`/api/v1/stats` field `memory.rss_kib` (the bench branch's merge reports it), and the QEMU self-test
boot also logs `selftest: vmrss: <kB>` at the end of its run; the trial confirms.

### P1: the frame, HOME, LIVE, DEVICES, the gate, the top alert

Before the update: `cargo xtask latency --json private/p1-before.json`, and from
`curl -s http://<pi>/api/v1/stats` note `memory.rss_kib` (KiB; the bench merge reports it, so the
Pi can be read directly now). The QEMU self-test's `selftest: vmrss: <kB>` line is the same figure
for a boot with no panel; the unit test `the_panels_buffers_and_caches_stay_within_the_memory_budget`
(`cargo test -p qberrypi --lib -- --nocapture the_panels_buffers`) prints the panel's own total.

- [ ] After the update's trial confirms: `cargo xtask latency --json private/p1-after.json`, then
